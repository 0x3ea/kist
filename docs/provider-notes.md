## 123云盘(webdav.123pan.cn,2026-08-20 实测)

来源:TODO-11 存在性探测压测——向 `/kist-loadtest/` 持续灌入小对象至万级,
逐检查点测 PROPFIND 完整性与时延(一次性工具,过程数据见 git 历史
`docs/todo/11-existence-probe.md` 与提交记录)。

| 特性 | 实测结论 |
|---|---|
| PROPFIND 完整性 | **不截断**:835 / 2281 / 4979 / 9950 对象四个检查点,三次连续列举的返回数与成功上传数逐一相符 |
| PROPFIND 时延 | 线性,≈2.2ms/对象:835→1.7s、2281→4.4s、4979→10s、9950→22s。万级库 gc 对账一次 20s+——分桶(远端布局 v2)属性能优化,不是正确性救命稻草 |
| PROPFIND Depth 0 | 支持(Probe 语义成立:存在→true+getcontentlength,404→false,单次 ~80–230ms) |
| 上传吞吐 | **按账号限速 ~100 请求/分钟,与并发无关**(4→8 并发吞吐不变)。批量导入与 migrate 的耗时下限由此决定:万对象 ≈100 分钟 |
| 上传失败率 | 累计 78/10000+ ≈ 0.8% 重试用尽;绝大多数是无退避重试的直接 4xx(限流的另一种形态),瞬时 5xx 稀少且可被 dav 层重试消化 |
| 整目录递归 DELETE | 支持(204),但有**秒级一致性延迟**:删除后立刻 PROPFIND 仍见幽灵 207,稍后才 404——"操作后立刻列举"的结果不可全信 |
| Range 断点续传 | 官方文档确认不支持(TODO-01 因此挂起;大文件运输走 TODO-13 出站箱) |

**对 kist 的直接含义**:gc 与 migrate 依赖的"整列 = 全量"假设在万级成立;
限速(而非时延或截断)才是批量操作的真正瓶颈;migrate 的对象粒度断点
续搬在限流场景下是必需品而非优化。

附注(工具教训):一次性压测工具也要有周期性进度输出——检查点之间
完全静默时,无法区分"在跑"与"挂了"。
