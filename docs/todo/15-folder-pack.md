# TODO-15 — 文件夹打包:put 压 zip 成单 blob,get 还原成文件夹

> 状态:候选(2026-08-21 需求讨论收敛;走单文件管线,不依赖 GUI,可先于大批量入库实施)
> 来源:漫画存档场景需求分析——作品/话/页三级结构,一话是原子消费单元

## 问题

- 现状 `put` 文件夹 = WalkDir 逐文件展开(`transfer/manager.go`),**每张图一个 blob + 一行索引 + 一张缩略图**;一话 200 页 → 远端 200 个互不关联的随机对象
- 按 123pan 实测([provider-notes.md](../provider-notes.md))记账,50 部 × 8 话 × 200 页 = 8 万页:

| 维度 | 散图直传(现状行为) | 一话打包 |
|---|---|---|
| 远端对象数 | 80,000 | 400 |
| 上传耗时下限 | 限速 ~100 请求/分钟 → **13+ 小时** | ~4 分钟 |
| gc/migrate 每次列举 | 8 万 × 2.2ms ≈ 3 分钟 | 忽略 |
| 索引库 | 8 万行 + 8 万缩略图 → GB 级,防抖备份整库放大(TODO-10 放大器的极端形态) | 400 行 |
| 下载一话 | 200 次 GET | 1 次 |

- 根因:**存储粒度(单文件)≠ 消费粒度(一话)**——看一话就是拿全部页,不会只取第 37 页

## 方案:pack 条目 = 明文恰好是 zip 的普通文件

`put` 遇文件夹默认打包成 zip 后走**现有单文件管线**;`get` 遇 pack 条目解压还原文件夹。blob 格式、远端布局、加密/重试/出站箱/migrate/gc/重名消解零改动:

| 机制 | pack 下的待遇 |
|---|---|
| BlobWriter/Reader、fileKey 派生、v2 填充 | 原样(明文区 = zip 字节流,padding 作用于流整体) |
| 出站箱 `--defer`、migrate、gc、孤儿清理 | 原样(单文件路径) |
| UniqueFileName "(1)" 递增、软删 | 原样 |

与「漫画专用格式」路线的界线(评估时否决):zip 是标准容器而非自造格式;作者/tag 等元数据仍归索引(查询面),不进内容;blobVersion 不新增演进分支;下载产物不依赖 kist 解包(灾难恢复场景的硬要求)。

### 打包粒度:递归下降,叶子目录成 pack

put 的目录树按唯一判据——**有无子目录**——解析,不看内容、不看名字:

| 传入形态 | 解析结果 |
|---|---|
| A/ 无子目录(纯文件) | A 整体一个 pack(单话作品形态) |
| A/ 含叶子子目录 A0/A1… | A 成为虚拟目录,A0/A1 各成一个 pack(多话作品形态) |
| 更深嵌套(如卷层) | 逐层下降,任何无子目录的叶子各自成 pack |
| 混杂层(散文件 + 子目录并存) | 散文件按普通文件各自入库(一文件一 blob,自带缩略图),子目录继续下降 |

- 示例:`put 作品A --dest /漫画/作品A`(各话为子目录)→ `/漫画/作品A/第01话[pack]…`,远端每话恰一个对象;"整部一个包"是被否决的粒度(补一话即重传整部);
- 显式覆盖:`--expand` 逐文件展开(混合内容目录);"强制整包"(多层结构想归为一个单元)记为可选增强,遇到真实需求再加。

### 上传侧

1. **校验遍**(只看名字/类型,不读字节;作用于整次 put 的全部待打包叶子,一遍收集全部问题再统一报错):
   - 文件名必须合法 UTF-8(`utf8.ValidString`)——非 UTF-8(如日漫 Shift-JIS 原始档)整次 put 拒绝,错误列出全部坏路径并提示 `convmv -f shift-jis -t utf8 -r --notest <目录>`;
   - symlink/FIFO/socket/设备文件:整次 put 拒绝,不静默跳过(存储器不静默丢东西)。
2. **打包遍**:`zip.NewWriter` 直挂 `BlobWriter` 之上,单遍流式,内存 ≈ 一块;jpg/png 已压缩用 **Store** 方法(无压缩收益,省 CPU);空目录显式写目录条目;条目 mtime 入 zip。
3. **封面**:打包时逐页过手,取第一页 `makeThumbnail` 一张(≤1/话,回到 thumbnails 的设计量级;TODO-10 若先行则改走封面 blob)。

### 下载侧

- GET → 解密到临时 zip(同现状 `.kistpart`)→ `zip.NewReader` → 解压到 `dest/.<名>.kistdirpart/` → **整体 rename**(同 FS 目录 rename 原子,接上单文件的原子落盘语义);失败/取消清理,不留半个目录。
- **解压断言**(纵深防御):条目名合法 UTF-8 + `filepath.Clean` 后不逃逸目标目录(与 zip-slip 同套检查);自家 zip 不应触发,触发即报错。
- 还原条目 mtime(`os.Chtimes`);目录自身 mtime 不保证。
- `--keep-zip`:跳过解压直接落 `.zip`(喂阅读器改名 `.cbz` 即用,kist 不必认识 cbz 这个词)。

### 索引建模

- schema v2:`files` 加 `pack INTEGER NOT NULL DEFAULT 0`(`user_version` 迁移机制现成)。
- **一行一话**;`size` 记 bucket(zipSize)——**pad 后显示值;真实 origSize 以 sealedMeta 为准,不得用索引 size 推明文长度/交付**(坑记录)。
- 原文件夹大小与条目数写 `user_meta` 供显示。
- `ls` 显示为文件夹条目;**不做 zip 内容穿透**(索引无内部结构,穿透 = 每次列目录解密整包)。

### CLI

- `put <目录>` 默认按「打包粒度」解析(无子目录整包、含子目录逐叶子成包);`--expand` 保留逐文件展开(混合内容文件夹"改一个文件即重传整包"的场景)。
- `get <uuid>` 默认还原成文件夹;`--keep-zip` 落 zip。

## 代价与缓解

- **padding 升档**:散图每张落 4KiB 档(总比例 ~1%)→ 整包落 >1MiB 的 10% 阶梯(60MB 话最多 +6MB)。量化粒度固有(TODO-08 本意),非打包新增层;绝对值可接受。
- **非字节级镜像**:编码/特殊文件/超长路径按"报错拒绝"处理,quickstart 明示可打包子集;Windows 保留名(CON/NUL 等)不防(明确不跨系统使用)。
- **put 默认行为变更**:quickstart 与 system-map 同步更新(项目约定:上手文档不落后于 CLI、现状图与代码一致)。
- `--recode shift-jis|gbk`(`golang.org/x/text`,纯 Go,显式源编码、不做自动嗅探):**可选增强**,遇到真实 Shift-JIS 档再补——嗅探必错一批,错比不转糟。

## 验收标准

- 往返:put 一话文件夹 → 远端恰 1 个新对象、索引 1 行、缩略图 ≤1 张;get 还原后逐文件 sha256 与 mtime 一致、目录结构一致(含空目录与空文件)
- 粒度:put 含子目录的作品目录 → 远端新对象数 = 叶子子目录数、父层成为虚拟目录;混杂层的散文件按普通文件入库
- 拒绝:非 UTF-8 名 / symlink / FIFO → put 报错并列出**全部**坏路径,远端零新对象、索引零新行
- 解压断言:构造含 `../` 逃逸或非 UTF-8 条目的 zip → 报错,目标处不落任何文件
- 原子性:加密/上传/解压任一环节中途取消或失败 → 无 `.kistpart`/`.kistdirpart` 残留
- `--expand` 走旧逐文件路径;`--keep-zip` 产物字节与明文区一致
- 收尾验收命令全绿:`go build ./... && go vet ./... && gofmt -l . && go test ./... -race -count=1`
