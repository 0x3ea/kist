# TODO-18 — 新建虚拟目录(CLI mkdir + GUI 新建文件夹)

> 状态:候选(2026-08-25 讨论:原诉求含"上传打包层级可选",收敛后砍掉——逐文件形态由「新建目录 + 批量上传文件」组合达成,见"范围外")
> 来源:用户无法先建结构再往里传——想建 /书/小说X 再批量传 epub,只能靠 put --dest 隐式建,或先传再 mv

## 现状核对(2026-08-25)

索引层与绑定层全部就绪,缺的只是入口:

- `index.EnsureFolderPath`:逐级 get-or-insert,天然幂等(mkdir -p 语义);
- GUI 绑定 `App.EnsureFolder`(按虚拟路径整链建,返回最深 id)——现只被移动对话框内部使用;
- CLI 无 mkdir 命令;GUI 工具栏无按钮。

虚拟目录是纯索引概念:不产生任何远端对象,零流量;空目录随 index.enc 备份同步到其他设备。

## 方案

### CLI:`mkdir <路径>`

- 多级创建、幂等(已存在不报错——与 `put --dest` 的宽容语义一致,不做 mkdir -p 与 mkdir 的区分);
- 路径从根写起,`..` 拒绝(splitVirtualPath 既有语义);只给 "/" 或空段时提示从第一级写起;
- 成功打印路径与 id,明示纯索引零流量。

### GUI:工具栏「新建文件夹」

- 点击弹输入对话框:在**当前目录**下创建(面包屑提示位置);输入允许 `a/b` 多级(EnsureFolder 按整路径逐级建);
- 建后刷新当前目录;重名时 EnsureFolderPath 幂等返回已有 id——不报错,行为与 CLI 一致。

## 范围外(讨论结论存档)

- **上传粒度选择(GUI 暴露 --expand 等价)不做**:批量上传**文件**从不打包——打包只作用于上传**文件夹**(叶子目录成 pack),多选文件经 UploadPaths 逐个独立入队独立成条。逐文件形态由「新建目录 → 进入 → 批量上传文件」组合达成;CLI 侧 `put --expand` 一直在。为组合可表达的形态不加旋钮(哑远端约束下的克制先例,同 06)。
- 更细的"打包深度"控制(如仅某层打包):同理组合可达(分层分次 put + mkdir/mv),不立项。
- GUI 的 `--defer`(出站箱)入口:维持 CLI 专属(quickstart 既有边界)。

## 涉及模块

- `cmd/kistctl/main.go`:cmdMkdir + usage 行 + dispatch(~30 行);
- 前端:Files.vue 工具栏按钮、新组件 NewFolderDialog.vue、store.ts 一个 createFolder 函数(~100 行);
- 零索引层改动、零管线改动、零 schema、零远端流量。

## 验收标准

- CLI:多级创建、重复执行幂等不报错、`..` 拒绝、根路径给出人话提示;
- GUI:当前目录下建立即可见;含 `/` 的输入建多级;取消无副作用;
- 建好的空目录出现在 `ls`,随 backup/pull 同步到新设备;
- 收尾验收命令全绿 + `npm run build`(vue-tsc)通过。
