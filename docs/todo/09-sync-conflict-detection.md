# TODO-09 — 同步冲突检测(SVN 式基线校验)

> 状态:候选(建议随 Phase 7 一并:启动自动 pull 与冲突对话框的宿主)
> 来源:2026-08 同步机制推演(与 GUI 自动备份同批接线)

## 问题:现状 LWW 在真并发下静默丢数据

- 裁决规则是「分歧后事务更多者通吃」:A 多次操作其他文件后改了 a.txt,B 只改了一次 a.txt → B 的修改被无声覆盖
- **平局盲区**:两边各写恰好一次 → 计数相等、内容不同,`==` 分支误判 noop,实际已分叉
- 唯一兜底是输家归档 `backups/`,但无任何提示

## 方案:客户端执法的 SVN 模型

远端是哑 WebDAV,没有服务器裁决,执法由客户端完成;约束时机在 **push**(不牺牲离线可写):

- `sync_state` 增加 `last_synced_rev`(基线:上次同步成功后双方一致的 revision)
- push 前探测远端 revision(读 index.enc 头部 Meta 即可),三方比较:

| 本地 vs 基线 | 远端 vs 基线 | 动作 |
|---|---|---|
| 未动 | 未动 | 无事,正常推 |
| 动过 | 未动 | 只有本机动过,放心推 |
| 未动 | 动过 | 本机干净,快进拉取(现三分支逻辑) |
| 动过 | 动过 | **分叉!停止,交给人裁决** |

- 冲突时提示用户选:保留本机(覆盖远端)/ 保留云端(本地归档,沿用 `ReplaceWith` 现有机制)
- 检测条件用「≠ 基线」而非「比大小」→ **顺带治好平局盲区**(两个 rev 21 也能识别为分叉)
- revision 角色从**裁判**(比大小定输赢)变为**证人**(只回答「谁动过」)

## 可选增强

- **启动自动 pull 廉价化**:Range 请求只拉 index.enc 头 156B 读 Meta(需服务器支持 Range;不支持则退化为整拉或 HEAD)
- **ETag/If-Match**:服务器支持时 push 升级为真 CAS(412 拒绝过期覆盖),不支持自动退化为客户端检测——只做增强,不做依赖

## 涉及模块

`internal/index`(sync_state 键)、`internal/backup`(push 侧检测、冲突结果类型)、CLI 提示与 GUI 冲突对话框。

## 验收标准

- 模拟双设备分叉:push 拒绝静默覆盖,给出冲突结果;两种选择各自的归档/覆盖行为正确
- 平局场景(两侧各写一次)被正确识别为冲突
- 同步成功后基线更新正确;快进路径行为与现状一致(不引入多余确认)
