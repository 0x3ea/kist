# TODO-14 — 操作审计日志(audit.log)

> 状态:候选(评估完成;体量小,可视为 TODO-07 补强随时插入)
> 来源:2026-08-20 会话推演——kist.log 只覆盖系统事件,命令级操作(何时、何事、成败)无档案

## 问题

- kist.log 是**系统视角**的诊断流水(传输起止、重试、孤儿、上下文俱全),但 5MB 单代轮转、短命
- **用户视角**的操作档案缺失:命令成功不留痕,失败只在屏幕一闪(07 的验收只到静默黑洞与传输起止,命令级出口未覆盖)
- 三个真实诉求:事后取证("上周删没删那个文件""最后一次 backup 何时"——多设备 LWW 环境尤其想要)、安全审计(unlock 口令试错时间线)、GUI"活动历史"页的数据地基

## 方案:main() 单点收口的 JSONL 账本

- 落点 `KIST_HOME/audit.log`,**每命令恰好一条 JSONL**,追加写、长留存(不随 kist.log 轮转;体积失控再议分月文件)
- `cmd/kistctl` 的 main 包一层:记录 ts、子命令、耗时、成败;失败附 AppError 错误码;按命令带少量摘要字段(put 的 files/bytes、migrate 的 copied/skipped/failed 等)
- 与 kist.log 的分工:**audit 回答 what/when(一行一命令),kist.log 回答 why(案发过程)**——同一次失败两边各就各位,时间戳可对齐
- 格式定死 JSONL 的理由:字段异构且值含中文/空格/等号;append-only 历史**格式一步定终身**(中途换格式会新旧混杂);消费者是程序(GUI 历史页、jq)在先、人在后
- 实现复用 07 的 slog 基建(JSONHandler)或直接 json.Marshal,约 30–50 行

## 红线与边界

- 隐私红线沿用:只记命令、路径、大小、错误码、耗时;**永不记**口令、密钥、URL 凭据、文件内容(--pass-stdin 本身不含秘密,KIST_PASS 走环境变量)
- **不进 SQLite**:写库推高 revision → 每敲一条命令触发一次备份放大,违背"状态库保持极小"的三层归属原则;审计是观测数据,不是状态,文件归属

## 涉及模块

`internal/audit`(新:Record + 文件打开 0600)、`cmd/kistctl`(main 收口);GUI 后置(活动历史页直接读 JSONL)

## 验收标准

- 每条命令恰好一行:时间、动作、耗时、成败;成功 put 带 files/bytes,失败带错误码
- unlock 口令错误被记录(动作 + 错误码,不含口令本体)
- JSONL 可被标准 JSON 逐行解析;中文文件名、含空格路径转义正确
- 长留存:kist.log 轮转不影响 audit.log
- 全文检索确认无口令/密钥/凭据/内容落盘

## 工作量

30–50 行 + 测试;小步插入。
