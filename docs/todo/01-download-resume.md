# TODO-01 — 下载断点续传

> 状态:候选(可行性高,建议 Phase 8 或独立小阶段)
> 来源:PLAN.md 后续计划第 1 项

## 背景与收益边界

- 只对「大文件 + 跨进程重启」有意义;同一会话内的瞬时失败已由 dav 层重试覆盖
- 建议小于 8MiB 的文件直接重下,不背状态管理

## 架构优势(既有设计自带)

- **块可寻址**:第 i 块密文偏移 = `156 + i×(chunkSize+16)`,每块独立解密(nonce 按序号派生)
- **blob 不可变**:随机名 + 永不改写(重传生成新对象)→ 无需 ETag/If-Range 一致性协商,只需核对总大小
- **安全性**:块认证 + 明文 SHA 终检保证错位续传只会报错拒绝落地,不会产出坏文件

## 协议

Range GET 是标准 HTTP,主流网盘支持(gowebdav 有现成 `ReadStreamRange`);需处理个别服务器忽略 Range 返回 200 的回退(整拉或放弃续传)。

## 改动范围(约 200–300 行,格式层零改动)

- 部分下载文件从 `/tmp/kist`(每次启动清空、失败即删)改为持久化到 `KIST_HOME/cache/`
- `.part` 伴状态文件记录已完成块,恢复时按块边界计算 Range 起点
- 失败/取消**保留** `.part`——行为变更,取消语义从「删除」改为「保留半成品」

## 验收标准

- 下载中途 kill 进程,重启后续传成功且内容与源一致(SHA 校验通过)
- `.part` 被篡改/错位时,续传以块认证失败或终检失败拒绝落地
- 取消后 `.part` 保留,可手动清理;小文件不产生 `.part`
